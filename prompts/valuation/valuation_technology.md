# Valuation Technology Axis Prompt

기술성 축을 평가한다.

평가 목표:
- 대상 특허의 기술적 문제 해결 방식, 핵심 구성의 구체성, 적용 가능성, 대체 기술 대비 차별 가능성을 평가한다.
- 단, 논문 인용, 제품 구현, 실제 성능 검증이 없으면 이를 단정하지 않는다.

사용 근거:
- 초록
- 대표 청구항
- 기술 분야
- 배경기술/해결 과제/해결 수단
- IPC/CPC
- summary_result
- 산업 RAG evidence
- portfolio_context

평가 기준:
- 높은 점수: 해결하려는 문제가 명확하고, 핵심 기술 구성이 구체적이며, 적용 가능한 기술 효과가 입력 근거에서 확인되는 경우
- 중간 점수: 기술 아이디어와 적용 분야는 확인되지만 구현 구체성이나 대체 기술 대비 차별성 판단에 추가 확인이 필요한 경우
- 낮은 점수: 기술 구성이 추상적이거나, 문제 해결 방식이 불명확하거나, 기술 차별성을 판단할 근거가 부족한 경우

주의:
- 특허 문헌에 처리량, 정확도, 신뢰성, ROI 같은 수치 검증이 없는 것은 일반적이므로, 그것만으로 기술성을 낮게 평가하지 않는다.
- 수치 검증이 없으면 “정량 검증은 별도 사업 검토 사항” 정도로 표현하고, “사업적 ROI 산정이 불가능”처럼 강하게 쓰지 않는다.
- citation이나 구현 단계가 없으면 confidence를 낮출 수는 있으나, 제공된 기술 내용에 기반해 점수 산정은 수행한다.
- 대상 특허의 기술 구성이 제품 전체의 핵심 차별점인지, 특정 기능·전처리·보조 모듈인지 구분한다.
- 현재 시장/기술 흐름에서 동일 문제를 해결하는 대체 접근이 확산되고 있는지 외부 근거와 입력 내용을 바탕으로 판단한다.
- 대체 기술 대비 성능 우위, 비용 절감, 정확도 개선, 적용 범위 확대 근거가 있으면 긍정 반영하되, 해당 근거가 없다는 이유만으로 결함처럼 단정하지 않는다.
- 산업 RAG evidence는 기술 동향 참고 근거로만 사용하고, 특허의 실제 구현 성능으로 단정하지 않는다.
- portfolio_context는 기술 범위 보완성과 특허군 시너지 판단에 사용한다.
- sibling 특허들이 하나의 공정 흐름, 제품 기능, 데이터 흐름, 제어 계층을 나누어 보호하면 대상 특허의 기술적 완성도와 적용 범위를 보완하는 근거로 반영한다.
- 단일 특허의 기술 구성이 좁더라도 sibling 특허들이 전후 공정이나 보완 기능을 보호해 전체 기술 체계를 형성하는지 판단한다.
- 입력에 없는 기술 효과나 성능 수치를 만들지 않는다.
