# Valuation Technology Axis Prompt

기술성 축을 평가한다.

기술성은 단순히 기술이 최신인지 평가하는 축이 아니다.

이 특허가 기존 기술과 비교했을 때 기술적으로 어떤 차별 요소가 존재하는지,
그리고 특허 기술이 실제 구현 가능한 수준으로 구체적으로 설명되어 있는지를 평가한다.

총점은 100점이며 반드시 아래 2개 하위 항목 점수를 합산한다.

1. 기술 차별성: 50점
2. 구현 구체성: 50점


평가 목적:
- 선행기술조사문헌과 유사 특허 비교군을 바탕으로 대상 특허의 기술 구성, 기술 동작 방식, 기술 효과 차별성을 평가한다.
- 대상 특허 문헌만을 바탕으로 실제 구현 가능한 수준까지 구체적으로 설명되어 있는지 평가한다.
- 사업부서가 이해할 수 있도록, 점수의 의미를 "이 기술이 왜 유지 검토에 기술적으로 의미가 있는지" 또는 "왜 보수적으로 봐야 하는지"로 연결해 설명한다.
- 법적 신규성/진보성, 권리범위의 법률적 강약, 시장성, 사업 적용 여부는 기술성 점수에 반영하지 않는다.


평가 원칙:
- 모든 출력 값은 반드시 한국어로 작성한다.
- 입력에 없는 성능 수치, 제품 구현, 실제 도입 사례를 만들지 않는다.
- `patent.document_role=target_patent`의 청구항·요약·명세서 내용만 대상 특허 기술로 서술한다.
- 대상 특허의 구성·절차·구현 구체성은 `patent.claim_context`와 `patent.technical_context`를 우선 사용한다.
- 독립항은 핵심 해결수단과 처리 흐름 판단에 사용하고, 종속항은 대체 구성·예외 조건·구현 변형·세부 제어 조건 판단에 사용한다.
- `technology_metrics.similar_patents`는 선행기술 또는 유사 비교문헌이다. 여기에만 존재하는 구성, 알고리즘, 효과를 대상 특허가 포함한다고 서술하지 않는다.
- 비교문헌에 `representative_claims`와 `technical_content`가 있으면 구성·동작·효과 비교에 우선 사용하고, 없으면 초록 또는 PDF 원문 범위에서만 판단한다.
- `element_structure`가 제공되면 대상/비교군의 주요구성요소(`element_structure.target.key_elements`·`element_structure.comparisons[].key_elements`)도 구성요소 대조 근거로 함께 활용한다.
- 대상 특허의 차별 요소는 대상 문헌에서 확인된 구성과 비교문헌에서 확인된 구성을 명시적으로 대조하여 작성한다.
- 예를 들어 비교문헌에만 퍼지 회귀가 있고 대상 청구항에 없다면, 퍼지 회귀를 대상 특허의 구현 또는 차별점으로 설명해서는 안 된다.
- 자료 부족은 특허의 약점처럼 단정하지 말고 `missing_information`과 `confidence`에 반영한다.
- 비교 문헌이 부족해도 평가를 회피하지 말고, 확보된 문헌 기준으로 판단하되 한계를 명시한다.
- 기술 차별성은 신규성/진보성 법률 판단이 아니라 기술적 차이 분석이다.
- 기술 차별성은 비교군 개수만 세는 방식이 아니라, 대상 특허의 구성·동작·효과 차이가 실제 기술 문제 해결 방식에 어떤 의미가 있는지 함께 판단한다.
- 구현 구체성은 구성요소·처리절차·구현설명의 존재 여부뿐 아니라, 해당 설명이 실제 구현자가 재현할 수 있을 정도로 구체적인지 판단한다.
- 기술성 설명에는 시장 성장성, 매출 가능성, SK AX 제품 적용 가능성, 침해 포착 가능성, 권리범위 강약을 섞지 않는다.
- 세부점수는 반드시 지정된 점수 후보 중 하나만 선택한다.
- `subscores.*.details`의 각 세부항목에는 점수와 상세 근거 객체를 작성한다.
- `score`는 반드시 두 하위 항목 점수 합계와 일치해야 한다.


사용 근거:
- 대상 특허 metadata
- 대상 특허 기술분야
- 대상 특허 배경기술
- 대상 특허 초록
- 대상 특허 해결하고자 하는 과제
- 대상 특허 과제의 해결 수단
- 대상 특허 대표 청구항
- 대상 특허 전체 청구항
- 대상 특허 sections
- `patent.technical_context`
- 발명을 실시하기 위한 구체적인 내용
- 실시예
- 도면 설명
- 시스템/장치 구성
- 처리 흐름
- 발명의 효과
- `technology_metrics.representative_cpc`
- `technology_metrics.representative_ipc`
- `technology_metrics.country_code`
- `technology_metrics.similar_patents`
  - `representative_claims`
  - `technical_content.problem`
  - `technical_content.solution`
  - `technical_content.effect`
  - `technical_content.detailed_description`
- `technology_metrics.target_document_indicators`
- `technology_metrics.similar_patents[].document_indicators`
- `technology_metrics.warnings`

- 국내특허는 CPC 기반, 해외특허는 IPC 기반 해당 국가 유사 특허 검색 결과

정량 보조지표 사용 규칙:
- `document_indicators`는 문서에 구현 관련 표현이 존재하는지 확인하는 참고값이며 세부점수를 자동 결정하지 않는다.
- 언급 횟수가 많다는 이유만으로 차별성, 구현 난이도 또는 구현 구체성을 높게 평가하지 않는다.
- 구성 요소와 절차의 실제 내용은 반드시 청구항, `technical_context`, `technical_content` 원문으로 확인한다.
- `embodiment_mentions`, `figure_mentions`, `formula_mentions`, `parameter_mentions`, `data_structure_mentions`는 구현 설명 및 기술적 활용 가능성의 참고값으로만 사용한다.
- `input_output_mentions`, `condition_branch_mentions`, `control_mentions`, `step_reference_mentions`는 구성 요소와 처리 절차 설명의 존재 여부를 확인하는 보조값으로만 사용한다.
- 대상 특허와 비교문헌에 같은 키워드가 존재한다는 사실만으로 기술적으로 동일하다고 판단하지 않는다.


----------------------------------------
1. 기술 차별성 (50점)
----------------------------------------

목적:
기존 기술과 비교했을 때 기술적으로 어떤 차별 요소가 존재하는지 평가한다.

사용 데이터:
- 대상 특허 PDF 원문
- 선행기술조사문헌 PDF 원문
- 유사 특허 PDF 원문
- KIPRIS 메타데이터
  - IPC/CPC
  - 출원인
  - 출원일

비교군 구성 기준:
- 선행기술조사문헌과 embedding similarity 기반 유사 특허를 함께 활용하여 비교군을 구성한다.
- 선행기술조사문헌은 실제 특허 심사 과정에서 관련성이 검토된 공식 비교 문헌으로 우선 활용한다.
- 추가 유사 특허는 심사 과정에서 반영되지 않은 유사 기술 가능성을 보완하기 위해 사용한다.
- 국내특허의 추가 유사 특허는 대표 CPC 기반으로, 해외특허의 추가 유사 특허는 대표 IPC 기반 해당 국가 문헌으로 수집된 것으로 간주한다.
- 비교군은 기술 관련성 및 중복성을 고려하여 총 5개 내외 특허로 구성된 것으로 간주하고 평가한다.

평가 방식:
- 대상 특허와 비교군 특허를 비교하여 기술 구성 차이, 기술 동작 방식 차이, 기술 효과 차이를 분석한다.
- 비교군 특허는 대상 특허 출원일 이전에 공개 또는 등록된 특허로 제한된 것으로 간주한다.
- PDF 원문이 있는 비교 문헌은 원문 수준 비교를 우선한다.
- PDF 원문이 없고 제목/초록/metadata만 있으면 비교 한계를 `missing_information`과 `confidence`에 반영한다.
- 비교군 전체를 확인하되 점수 구간은 대상 특허의 핵심 해결수단과 가장 가까운 비교문헌을 기준으로 선택한다.
- 단순히 몇 개 문헌과 차이가 있는지 세지 않는다. 가장 가까운 비교문헌이 핵심 구성·처리 흐름·효과를 대부분 포함하면 다른 문헌과 차이가 있더라도 고득점하지 않는다.

비교 절차:
1. 대상 특허의 독립항, 주요 종속항, `technical_context.problem`, `technical_context.solution`, `technical_context.detailed_description`에서 아래 항목을 추출한다.
   - 해결과제
   - 핵심 구성요소
   - 각 구성의 역할과 입력·출력
   - 구성 간 연결·호출·의존·제어 관계
   - 입력부터 출력까지의 주요 처리 단계
   - 판단 조건, 계산 방식, 데이터 변환 및 제어 방식
2. 각 비교문헌의 `representative_claims`, `technical_content`, 초록 또는 PDF 원문에서 같은 항목을 추출한다.
3. 목적이나 명칭의 유사성이 아니라 핵심 해결수단의 구조와 작동 원리가 가장 가까운 문헌을 식별한다.
4. 대상 특허와 가장 가까운 비교문헌을 같은 비교 단위끼리 대조한다.
5. 확인된 차이가 핵심 해결수단을 바꾸는 차이인지, 보조 단계·적용 조건·파라미터 수준인지 구분한다.
6. 각 점수의 모든 문구를 동시에 만족할 필요는 없지만, 선택한 점수의 핵심 조건과 실제 근거가 일치해야 한다.

점수화 기준:

구성·동작 방식 차별성 (25점)
- 사용 재료:
  - 대상: 독립항, 주요 종속항, 해결과제, 해결수단, 상세설명, 도면의 처리 흐름
  - 비교: 가장 가까운 비교문헌의 대표 청구항, 해결수단, 상세설명, 초록
- 비교 단위:
  - 핵심 구성, 구성의 역할, 구성 간 관계, 처리 순서, 판단 주체·조건, 데이터 생성·변환·전달, 제어 방식
- 25점:
  - 가장 가까운 비교문헌과 해결 목적 일부가 같더라도 문제 해결에 필수적인 핵심 구성요소 또는 구성 간 결합 관계가 다르다.
  - 주요 처리 단계의 순서, 판단 로직, 데이터 흐름 또는 제어 방식이 달라 별도의 작동 원리를 형성한다.
  - 확인된 차이를 제거하거나 비교문헌 방식으로 대체하면 대상 특허의 핵심 처리 결과 또는 작동 방식이 유지되기 어렵다.
- 17점:
  - 기반 구성이나 해결 목적 일부는 비교문헌과 공통이다.
  - 다만 핵심 구성의 조합·역할 배치 또는 주요 처리 단계 중 하나 이상에 차이가 있고, 그 차이가 최종 출력이나 핵심 작동 방식에 실질적인 영향을 준다.
  - 단순한 명칭 변경, 적용 산업 변경 또는 부가 기능 추가만으로 17점을 선택하지 않는다.
- 8점:
  - 독립항의 주요 구성요소와 전체 처리 흐름이 비교문헌에 대부분 존재한다.
  - 차이는 종속항의 보완 기능, 전처리·후처리, 적용 대상, 임계값, 파라미터, 예외 조건 또는 세부 제어 수준이다.
  - 해당 차이를 제거해도 핵심 해결 구조와 주요 결과가 대체로 유지된다.
- 0점:
  - 가장 가까운 비교문헌이 대상 독립항의 핵심 구성과 주요 처리 흐름을 실질적으로 대부분 포함하고, 별도의 핵심 조합이나 작동 차이가 확인되지 않는다.
  - 또는 대상 청구항이나 비교문헌의 청구항·상세 초록이 없어 구성·동작 차이를 판단할 수 없다.

기술 효과 차별성 (15점)
- 사용 재료:
  - 대상: 해결과제, 발명의 효과, 해결수단, 상세설명
  - 비교: 가장 가까운 비교문헌의 효과, 해결수단, 상세설명 또는 초록
  - 선행 단계에서 확인한 구성·동작 차이
- 판단 절차:
  1. 대상과 비교문헌의 효과를 정확도·속도·안정성·자원 절감 같은 효과 문구만으로 비교하지 않는다.
  2. 어떤 구성 또는 처리 차이가 어떤 효과를 발생시키는지 인과관계를 확인한다.
  3. 대상 문헌에 없는 정량 성능 향상이나 효과 발생 원리를 추정하지 않는다.
- 15점:
  - 대상 특허의 핵심 구성·동작 차이에서 비교문헌에 없는 별도의 기술적 효과가 직접 발생한다.
  - 차이 요소와 효과 사이의 인과관계가 해결수단·효과·상세설명에서 구체적으로 확인된다.
- 10점:
  - 전체 효과 방향은 일부 유사하지만 대상 특허의 핵심 구성 또는 처리 흐름 차이로 인해 별도의 효과가 추가된다.
  - 별도 효과와 차이 요소의 연결관계가 문헌에서 확인된다.
- 5점:
  - 효과의 종류와 발생 원리가 비교문헌과 대체로 동일하다.
  - 차이는 성능 정도, 처리 범위, 적용 조건·환경 또는 일반적인 개선 표현 수준이다.
- 0점:
  - 비교문헌이 대상 특허의 주요 효과와 발생 원리를 대부분 포함하고 별도 효과가 확인되지 않는다.
  - 또는 대상·비교문헌의 효과나 구성·동작과 효과의 연결 근거가 없어 차별성을 판단할 수 없다.

모방·회피 난이도 (10점)
- 사용 재료:
  - 대상: 핵심 구성, 구성 간 의존관계, 처리 단계, 판단 로직, 파라미터·제어 조건, 종속항의 변형·예외 조건
  - 비교: 유사특허에서 확인되는 동일 문제의 다른 해결 구조와 대체 구현 방식
  - 보조값: 조건·분기·제어·단계·파라미터 관련 `document_indicators`
- 판단 원칙:
  - 법적 권리범위, 침해 성립 또는 청구항 회피 가능성을 판단하지 않는다.
  - 동일하거나 유사한 기술 효과를 다른 기술 구조로 재현하는 데 필요한 기술적 노력만 평가한다.
  - 단순히 구성 수나 처리 단계 수가 많다는 이유로 난이도를 높게 평가하지 않는다.
- 10점:
  - 동일 효과를 재현하려면 여러 핵심 구성의 정밀한 결합, 복수 단계의 상호 의존, 전문 알고리즘 또는 특수 제어 조건이 함께 필요하다.
  - 핵심 요소 하나를 통상적인 대체 구성으로 바꾸면 주요 효과가 유지되기 어렵고, 비교문헌에서도 유사한 대체 구조가 확인되지 않는다.
- 7점:
  - 일부 구성이나 알고리즘은 대체할 수 있다.
  - 그러나 동일 수준의 효과를 안정적으로 구현하려면 처리 흐름 재설계, 파라미터 조정, 예외 처리 또는 복수 구성의 최적화가 필요하다.
- 3점:
  - 핵심 아이디어는 확인되지만 구성 간 의존성이 낮다.
  - 관련 분야의 통상적인 모듈·알고리즘·데이터 처리 방식에 일부 수정을 가하면 유사한 효과를 구현할 수 있다.
- 0점:
  - 단순 구성 연결, 일반적인 순차 처리, 통상적인 조건 분기 또는 알려진 모듈의 단순 조합으로 핵심 효과를 쉽게 재현할 수 있다.
  - 또는 대체 구현 가능성과 기술적 의존관계를 판단할 대상 상세설명·비교문헌이 부족하다.

`subscores.technical_differentiation.score`는 위 3개 세부점수의 합계로 0~50점 범위에서 산정한다.

`subscores.technical_differentiation.details`에는 아래 세부점수와 상세 근거 객체를 작성한다.
- `configuration_operation_differentiation`: 0, 8, 17, 25 중 하나
- `effect_differentiation`: 0, 5, 10, 15 중 하나
- `imitation_avoidance_difficulty`: 0, 3, 7, 10 중 하나

2. 구현 구체성 (50점)
----------------------------------------

목적:
특허 기술이 실제 구현 가능한 수준으로 구체적으로 설명되어 있는지를 평가한다.

사용 데이터:
- 대상 특허 PDF 원문

평가 방식:
- 대상 특허 PDF 원문을 바탕으로 청구항, 상세설명, 도면에서 기술 구성 요소, 처리 절차, 기술 동작 방식 및 구현 설명을 분석한다.
- 구현 구체성은 비교문헌과 비교하지 않고 대상 특허 자체만 평가한다.
- 청구항에 구성이나 단계가 기재되어 있다는 사실만으로 구체적이라고 판단하지 않는다. 상세설명·도면에서 역할, 입력·출력, 관계, 조건 및 실행 흐름이 설명되는지 확인한다.

점수화 기준:
구성 요소 구체성 (20점)
- 사용 재료: 독립항, 종속항, 해결수단, 상세설명, 도면 설명, 대표 도면 상세
- 확인 단위: 구성요소 명칭, 책임·역할, 입력, 처리 결과·출력, 다른 구성과의 연결·호출·의존 관계
- 20점:
  - 핵심 구성요소별 역할, 입력, 처리 결과, 출력 및 상호관계가 확인된다.
  - 독립항의 핵심 구성이 상세설명이나 도면의 실제 시스템 구조와 연결되어 구현자가 각 구성의 책임과 데이터 교환 방식을 파악할 수 있다.
- 14점:
  - 주요 구성요소와 기본 역할은 확인된다.
  - 다만 일부 구성의 입력·출력, 호출 관계, 데이터 전달 방식 또는 연결 조건이 생략되어 세부 인터페이스에는 추가 설계가 필요하다.
- 7점:
  - 구성요소의 명칭이나 기능만 나열되고 내부 역할·입출력·상호작용이 추상적이다.
  - 필요한 구성은 알 수 있지만 구체적인 결합 구조를 문헌만으로 설계하기 어렵다.
- 0점:
  - 핵심 구성요소를 식별하기 어렵거나 기능적 결과만 제시되어 시스템 구조를 구성하기 어렵다.

처리 절차 구체성 (20점)
- 사용 재료: 방법 독립항, 종속항, 상세설명, 도면의 단계 번호, 처리 흐름과 제어 설명
- 확인 단위: 시작 조건, 단계별 입력, 수행 처리, 판단 조건, 분기·반복, 데이터 변환·전달, 출력 및 제어 흐름
- 20점:
  - 시작 조건부터 최종 출력까지 단계별 입력, 수행 처리, 판단 조건, 분기, 데이터 변환, 출력 및 제어 흐름이 설명된다.
  - 방법 청구항·상세설명·도면 단계가 대응되어 구현 순서를 재구성할 수 있다.
- 14점:
  - 주요 처리 단계와 순서는 확인된다.
  - 다만 일부 단계의 입력·출력, 조건 분기, 반복 조건, 예외 처리 또는 데이터 전달 관계가 제한적으로 설명된다.
- 7점:
  - 전체 처리 순서만 개략적으로 제시되고 각 단계가 사용하는 데이터, 수행 내용, 판단 기준 또는 생성 결과가 불명확하다.
- 0점:
  - 기능이나 최종 결과만 제시되고 단계별 처리 절차와 흐름을 확인하기 어렵다.

구현 설명 및 기술적 활용 가능성 (10점)
- 사용 재료: 실시예, 도면, 산식, 파라미터, 데이터 구조, 제어 조건, 변형 예시, 적용 대상·실행 환경
- 보조값: 실시예·도면·산식·파라미터·데이터 구조 관련 `target_document_indicators`
- 10점:
  - 실시예·도면·산식·파라미터·데이터 구조·제어 조건·변형 예시 중 복수 자료가 실제 내용과 함께 제공된다.
  - 적용 대상과 실행 환경이 구현 구조에 연결되어 구현자가 새로운 핵심 발명을 추가하지 않고 실제 적용 구조를 설계할 수 있다.
- 7점:
  - 적용 대상과 기본 구현 방향을 파악할 수 있고 실시예나 도면 등 참고자료가 존재한다.
  - 다만 일부 파라미터, 데이터 구조, 제어 조건, 예외 상황 또는 변형 예시가 부족하다.
- 3점:
  - 적용 분야나 사용 목적은 제시되지만 구현 설명이 기능적·포괄적 표현에 머문다.
  - 실제 적용을 위해 알고리즘, 데이터 구조, 인터페이스 또는 제어 조건을 상당 부분 추가 설계해야 한다.
- 0점:
  - 실시예나 구현 참고정보가 없고 실제로 어디에 어떻게 적용할 수 있는지 판단하기 어렵다.

`subscores.implementation_specificity.score`는 위 3개 세부점수의 합계로 0~50점 범위에서 산정한다.

`subscores.implementation_specificity.details`에는 아래 세부점수와 상세 근거 객체를 작성한다.
- `component_specificity`: 0, 7, 14, 20 중 하나
- `procedure_specificity`: 0, 7, 14, 20 중 하나
- `implementation_utilization_specificity`: 0, 3, 7, 10 중 하나

- 시장 규모, 사업 적용 여부, 매출 가능성을 기술성 점수에 반영하지 않는다.
- `subscores.technical_differentiation.rationale`에는 가장 가까운 비교문헌의 식별값 또는 제목, 공통 핵심 구성, 대상 특허에 남는 구성·처리 차이, 그 차이에서 발생하는 효과, 대체 구현 난이도를 종합하여 작성한다.
- 기술 차별성 rationale에서 "차별성이 있다", "의미 있는 차이가 있다"만 반복하지 말고 어떤 구성·단계·조건이 어떻게 다른지 작성한다.
- `subscores.implementation_specificity.rationale`에는 구성 요소, 처리 절차, 구현 설명의 구체성을 종합 요약하되 세부점수 항목명을 나열하지 않는다.
- 구현 구체성 rationale에는 확인된 입력·출력·상호관계·조건·분기·실시예 중 구체적 근거와, 추가 설계가 필요한 부분을 함께 작성한다.
- `rationale`에는 사업부서가 이해할 수 있도록 "구현 가능성", "비교군 대비 실질 차이", "유지 검토에 주는 기술적 의미"를 한 문단으로 연결한다.

세부 근거 객체 공통 규칙:
- `score`: 해당 항목의 고정 점수 후보 중 하나
- `assessment_status`: 실제 평가를 수행했으면 `evaluated`, 자료 부족으로 판단하지 못했으면 `insufficient_evidence`
- `target_basis`: 대상 특허에서 확인한 청구항 번호, 구성, 단계, 조건, 효과 또는 구현 설명

- `common_points`: 대상과 비교문헌의 공통점 또는 대상 문헌에서 확인된 구현 설명
- `difference_points`: 대상에 남는 기술 차이 또는 누락·불명확한 구현 설명
- `score_reason`: 위 근거가 해당 점수 구간에 해당하는 구체적인 이유
- `missing_information`: 자료 부족 항목. 자료가 충분하면 빈 배열
- `score_reason`에 "의미 있는 차이", "구체적임", "난이도가 높음"만 쓰지 말고 실제 구성·단계·입출력·조건과 점수 경계를 연결한다.
