# Valuation Technology Axis Prompt

기술성 축을 평가한다.

기술성은 단순히 기술이 최신인지 평가하는 축이 아니다.

이 특허가 단순 아이디어 수준이 아니라 실제 구현 가능한 수준으로 구체화되어 있는지,
기존 기술 또는 유사 특허 대비 기술적 구조와 해결 방식이 구별되는지,
그리고 문헌에 기재된 효과가 실제 기술적 개선으로 연결되는지를 평가한다.

총점은 100점이며 반드시 아래 3개 하위 항목 점수를 합산한다.

1. 기술 완성도·실현 가능성: 45점
2. 기술 차별성: 35점
3. 기술 유용성: 20점


평가 순서:
1. 먼저 대상 특허의 기술 구성, 해결수단, 실시예, 발명의 효과를 바탕으로 기술 내용을 요약한다.
2. 기존 기술 또는 유사 기술과 비교하여 차별 요소를 판단한다.
3. 기술 완성도·실현 가능성, 기술 차별성, 기술 유용성을 각각 평가한다.
4. 마지막으로 각 하위 항목에서 지정된 점수 후보 중 가장 가까운 점수를 선택한다.
5. 점수는 반드시 앞서 판단한 기술적 근거와 일치해야 한다.


평가 목적:
- 대상 특허 문헌 안에 구현에 필요한 구성요소, 처리 흐름, 동작 원리, 실시예가 얼마나 구체적으로 제시되어 있는지 평가한다.
- 기존 기술 또는 유사 특허 대비 기술적 접근, 구조, 해결 방식이 얼마나 다른지 평가한다.
- 발명의 효과가 단순 선언이 아니라 해결수단과 연결된 기술적 개선인지 평가한다.
- 법적 신규성/진보성, 권리범위, 회피설계 가능성, 시장성, 사업 적용 여부는 기술성 점수에 반영하지 않는다.


평가 원칙:
- 모든 출력 값은 반드시 한국어로 작성한다.
- 입력에 없는 성능 수치, 제품 구현, 실제 도입 사례를 만들지 않는다.
- 하위 항목 점수는 반드시 지정된 점수 후보 중 하나만 선택한다.
- 체크리스트는 판단 보조로만 사용하고, 체크리스트 개수로 기계적으로 점수를 합산하지 않는다.
- 기술 완성도·실현 가능성과 기술 유용성은 대상 특허 문헌을 중심으로 판단한다.
- 기술 차별성은 비교 가능한 기존 기술/유사 특허 근거를 사용하되, 신규성/진보성 판단처럼 단정하지 않는다.
- 유사 특허 존재만으로 기술 차별성이 낮다고 자동 판단하지 않는다.
- 비교 문헌이 부족하면 기술 차별성의 판단 한계를 missing_information과 confidence에 반영한다.
- 자료 부족은 특허의 약점처럼 단정하지 말고 confidence에 반영한다.
- "추가 검토 필요"만 쓰고 평가를 회피하지 않는다.
- 점수 합계는 반드시 하위 항목 합계와 일치해야 한다.


사용 근거:
- 대상 특허 metadata
- 대상 특허 기술분야
- 대상 특허 배경기술
- 대상 특허 초록
- 대상 특허 해결하고자 하는 과제
- 대상 특허 과제의 해결 수단
- `claim_context.independent_claims`
- 대상 특허 sections
- 발명을 실시하기 위한 구체적인 내용
- 실시예
- 도면 설명
- 시스템/장치 구성
- 처리 흐름
- 발명의 효과
- summary_result
- `technology_metrics.representative_cpc`
- `technology_metrics.similar_patents`
  - 제목, 초록, 유사도, 출원일, 출원인, 상태
  - PDF 수집 성공 시 `pdf_text` 또는 `pdf_text_excerpt`
- `technology_metrics.prior_art_patents`
- `citation_evidence`
- `prior_art_candidates`
- CPC/IPC 기반 유사 특허 검색 결과
- `technology_metrics.warnings`
- portfolio_context는 보조 근거로만 사용한다.


----------------------------------------
1. 기술 완성도·실현 가능성 (45점)
----------------------------------------

목적:
이 기술이 단순 개념 제안이 아니라, 실제 구현 가능한 수준까지 기술적으로 구체화되어 있는지 평가한다.

사용 정보:
- 발명을 실시하기 위한 구체적인 내용
- 과제의 해결 수단
- 실시예
- 도면 설명
- 시스템/장치 구성
- 처리 흐름
- 독립항

판단 체크리스트:
- 입력 정보, 처리 대상, 출력 결과가 명확한가?
- 처리 절차가 단계별로 설명되어 있는가?
- 계산, 판단, 제어, 학습, 갱신 로직이 설명되어 있는가?
- 구현에 필요한 구성요소 간 관계가 설명되어 있는가?
- 실시예나 도면으로 실제 동작이 뒷받침되는가?
- 추가 미완성 기술 없이는 구현이 어려운 구조인가?

점수 후보:
45:
구성요소, 처리 흐름, 동작 원리, 실시예가 구체적으로 제시되어 실제 구현 가능성이 매우 높음

36:
전반적으로 구현 구조는 구체적이나 일부 세부 구현 방식은 추상적임

27:
핵심 개념과 흐름은 제시되나 실제 구현을 위해 상당한 추가 설계가 필요함

15:
기능 또는 아이디어 수준 설명이 중심이며 구현 구조가 불명확함

0:
구현 판단에 필요한 기술 정보가 부족함


----------------------------------------
2. 기술 차별성 (35점)
----------------------------------------

목적:
기존 기술 대비 기술적 접근, 구조, 해결 방식이 얼마나 다른지 평가한다.

사용 정보:
- 대상 특허의 기술분야
- 배경기술
- 해결하고자 하는 과제
- 과제의 해결 수단
- 독립항
- 유사 특허 후보
- citation_evidence
- prior_art_candidates
- CPC/IPC 기반 유사 특허 검색 결과

기존 기술 확보 우선순위:
1순위: 대상 특허가 직접 인용한 선행/유사 문헌
2순위: KIPRIS/Google Patents에서 검색한 유사 특허 후보
3순위: 같은 IPC/CPC와 핵심 키워드가 겹치는 공개/등록 특허
4순위: 논문·기술 리포트·제품 기술자료

판단 체크리스트:
- 기존 기술과 다른 기술 구조가 있는가?
- 같은 문제를 다른 방식으로 해결하는가?
- 데이터/신호/공정/제어 흐름이 다른가?
- 단순 조합이 아니라 기술적 독창성이 있는가?
- 차별 요소가 특허 문서 근거로 확인되는가?

평가 규칙:
- `technology_metrics.prior_art_patents`와 `technology_metrics.similar_patents`를 비교 근거로 사용한다.
- PDF 원문이 있는 비교 문헌은 대상 특허 문헌과 원문 수준으로 비교한다.
- PDF 원문이 없고 제목/초록/metadata만 있으면 비교 한계를 명시한다.
- 차별성은 "다르다"라고만 쓰지 말고, 어떤 구성요소, 조합, 처리 흐름, 해결 방식이 다른지 설명한다.
- 기존 기술 비교는 신규성/진보성 판단이 아니라 기술적 차별성 판단용이다.

점수 후보:
35:
기존 기술 대비 기술 구조와 해결 방식의 차별성이 매우 명확함

28:
차별 요소가 확인되나 일부 구성 또는 접근 방식은 기존 기술과 유사함

20:
기존 기술과의 차이가 제한적이며, 개선·변형 수준에 가까움

10:
기술적 차별 요소가 약함

0:
비교 가능한 기존 기술 정보가 부족함


----------------------------------------
3. 기술 유용성 (20점)
----------------------------------------

목적:
해당 기술이 실제 기술적 개선 효과를 제공하는지 평가한다.
기술 유용성에서의 "효과"는 반드시 수치 실험 결과일 필요는 없다.
특허 문헌에 기재된 발명의 효과, 해결과제, 실시예를 기준으로 판단한다.

다만 효과가 단순히 "성능 향상", "효율 개선", "편의성 향상"처럼 선언적으로만 기재되어 있고,
어떤 기술 구성 또는 해결수단으로 인해 해당 효과가 발생하는지 연결되지 않으면 낮게 평가한다.

사용 정보:
- 발명의 효과
- 해결하고자 하는 과제
- 실시예
- 상세한 설명
- 성능 개선, 효율 향상, 안정성 향상, 자동화 효과 관련 문장

판단 체크리스트:
- 기존 문제를 해결하는 효과가 명확한가?
- 성능, 정확도, 속도, 효율, 안정성, 품질 개선이 있는가?
- 자동화, 운영 효율, 자원 절감 효과가 있는가?
- 효과가 단순 선언이 아니라 기술 구성과 연결되어 있는가?
- 효과가 특정 상황에만 제한되지 않고 의미 있게 활용 가능한가?

점수 후보:
20:
기술적 개선 효과가 명확하고, 해결수단과 효과의 연결이 구체적임

16:
개선 효과가 확인되나 일부 효과는 선언적이거나 근거가 약함

10:
효과는 있으나 적용 범위나 개선 수준이 제한적임

4:
효과 설명이 추상적이고 실제 기술적 개선이 불명확함

0:
효과 판단에 필요한 정보가 부족함

- 시장 규모, 사업 적용 여부, 매출 가능성을 기술성 점수에 반영하지 않는다.
