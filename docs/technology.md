# 기술성 평가 기준 및 구현 계획

기술성 평가는 대상 특허의 기존 기술 대비 차별성과 문헌 내 구현 구체성을 종합해 100점 만점으로 산정한다.

```text
기술성 점수(100)
= 기술 차별성(60)
+ 구현 구체성(40)
```

## 1. 기술 차별성 (50점)

### 목적

기존 기술과 비교했을 때 대상 특허가 기술적으로 무엇이 다른지 평가한다.

### 사용 데이터

- 대상 특허 PDF 원문
- 선행기술조사문헌 PDF 원문
- 유사 특허 PDF 원문

### 평가 방식

```text
대상 특허 입력
→ KIPRIS API로 대상 특허 메타데이터 조회
→ 대상 특허 PDF 원문 수집
→ 대상 특허의 제목·초록·대표 청구항·기술 구성 추출
→ 대표 CPC 또는 IPC 추출
→ 국내특허는 대표 CPC, 해외특허는 대표 IPC와 국가 기준으로 유사 특허 후보 검색
→ 대상 특허 출원일 이전 특허 필터링
→ 대상 특허 출원일 기준 최근 10년 특허 필터링
→ 개인 출원 제외 필터링
→ 후보 유사 특허 메타데이터 조회
→ 후보 유사 특허의 제목·초록 추출
→ 제목+초록 기반 embedding similarity 계산
→ 선행기술조사문헌 우선, 부족분은 유사도 상위 문헌으로 보완해 총 5개 내외 비교군 구성
→ 비교군 특허 PDF 원문 수집
→ LLM이 대상 특허와 비교군 특허 비교
→ 공통 기술 요소 및 차별 기술 요소 추출
→ 기술 구조 차별 요소 분석
→ 기술 차별성 점수 산정
```

### 판단 요소

| 판단 요소 | 설명 |
| --- | --- |
| 기술 구조 차별성 | 기존 유사 특허 대비 새로운 구성요소 및 기술 조합 차이가 존재하는지 |
| 기술 동작 방식 차별성 | 처리 순서, 판단 로직, 제어 방식, 데이터 흐름이 비교군과 다른지 |
| 기술 효과 차별성 | 구성·동작 차이에서 직접 도출되는 효과가 비교군과 다른지 |

### 점수화 기준

| 평가 항목 | 판단 기준 | 점수 |
| --- | --- | ---: |
| 신규 구성요소 존재 | 유사 특허에 없는 새로운 구성요소가 확인됨 | 15 |
| 기술 조합 차별성 | 기존 구성요소를 결합하는 방식이 다름 | 15 |
| 처리 구조 차별성 | 데이터·신호·공정·제어 흐름이 유사 특허와 다름 | 15 |
| 해결 방식 차별성 | 같은 문제를 다른 방식으로 해결하거나 다른 기술적 효과를 냄 | 10 |
| 차별 근거 명확성 | 차별 요소가 청구항·상세설명 등 문서 근거로 확인됨 | 5 |
| 합계 |  | 60 |

## 2. 구현 구체성 (50점)

```text
구현 구체성 점수(40)
= 구성 요소 구체성(15)
+ 처리 절차 구체성(15)
+ 구현 설명 구체성(10)
```

## 2-1. 구성 요소 구체성 (20점)

### 목적

기술 구현에 필요한 구성 요소와 각 역할·상호관계가 구체적으로 설명되어 있는지를 평가한다.

### 사용 데이터

- 대상 특허 PDF 원문

### 판단 요소

| 판단 요소 | 설명 |
| --- | --- |
| 구성 요소 명시 | 필요한 장치, 모듈, 데이터, 처리 대상이 확인되는지 |
| 역할 설명 | 각 구성 요소가 어떤 기능을 하는지 설명되는지 |
| 상호관계 설명 | 입력, 처리, 출력 또는 모듈 간 연결 관계가 설명되는지 |

### 점수화 기준

| 평가 항목 | 판단 기준 | 점수 |
| --- | --- | ---: |
| 구체적 | 구성 요소와 각 역할·상호관계가 구체적으로 설명됨 | 15 |
| 일부 구체적 | 주요 구성 요소와 역할은 설명되나 상호관계 또는 입력·출력이 일부 제한적임 | 10 |
| 개략적 | 구성 요소 명칭은 있으나 역할 설명이 추상적임 | 5 |
| 확인 어려움 | 구현에 필요한 구성 요소를 확인하기 어려움 | 0 |

## 2-2. 처리 절차 구체성 (20점)

### 목적

기술 구현에 필요한 단계별 처리 절차와 조건·흐름이 구체적으로 설명되어 있는지를 평가한다.

### 사용 데이터

- 대상 특허 PDF 원문

### 판단 요소

| 판단 요소 | 설명 |
| --- | --- |
| 처리 절차 제시 | 단계별 처리 흐름 또는 수행 절차가 설명되는지 |
| 조건·분기 설명 | 조건, 분기, 반복, 판단 기준이 설명되는지 |
| 데이터 흐름 설명 | 입력에서 산출물까지의 흐름이 설명되는지 |

### 점수화 기준

| 평가 항목 | 판단 기준 | 점수 |
| --- | --- | ---: |
| 구체적 | 단계별 처리 절차와 조건·흐름이 구체적으로 설명됨 | 15 |
| 일부 구체적 | 주요 단계는 설명되나 조건, 분기, 데이터 흐름이 일부 제한적임 | 10 |
| 개략적 | 처리 순서가 개략적으로만 제시됨 | 5 |
| 확인 어려움 | 단계별 처리 절차를 확인하기 어려움 | 0 |

## 2-3. 구현 설명 구체성 (10점)

### 목적

기술 동작 방식 또는 구현 방식이 실제 구현자가 참고할 수 있는 수준으로 설명되어 있는지를 평가한다.

### 점수화 기준

| 평가 항목 | 판단 기준 | 점수 |
| --- | --- | ---: |
| 충분함 | 기술 동작 방식, 산식, 파라미터, 실시예, 도면 등 구현자가 참고할 설명이 충분함 | 10 |
| 일부 제한 | 구현 방향은 알 수 있으나 세부 산식, 조건, 예시, 변형 설명이 제한적임 | 5 |
| 확인 어려움 | 구현 방식 설명이 추상적이거나 확인되지 않음 | 0 |

## 구현 반영 계획

### 1. 유사 특허 후보 수집

- 국내특허는 전처리된 metadata의 대표 CPC를 사용한다.
- 해외특허는 전처리된 metadata의 대표 IPC와 출원국가를 함께 사용한다.
- 선행기술조사문헌이 있으면 우선 비교군으로 사용하고, 부족분은 유사 특허 검색으로 보완한다.
- 후보 필터:
  - 대상 특허와 같은 국가 또는 비교 가능한 공개/등록 특허
  - 대상 특허 출원일 이전
  - 대상 특허 출원일 기준 최근 10년
  - 대상 특허 자기 자신 제외
  - 개인 출원 제외

### 2. 비교군 특허 선정

- 후보의 `title + abstract`와 대상 특허의 `title + abstract`를 embedding한다.
- 선행기술조사문헌을 먼저 사용하고, 부족하면 cosine similarity 기준 상위 문헌을 보완해 총 5개 내외 비교군을 구성한다.
- 비교군 특허 PDF는 가능한 경우 수집하고 markdown으로 파싱한다.
- PDF 수집 실패 시 제목/초록/청구항 metadata만으로 비교하되, missing 정보에 남긴다.

### 3. 기술성 LLM 입력

기술성 prompt에는 아래 값을 추가한다.

```json
{
  "technology_metrics": {
    "representative_cpc": "...",
    "representative_ipc": "...",
    "country_code": "...",
    "comparison_mode": "hybrid",
    "similar_patents": [],
    "target_count": 5,
    "candidate_count": 0,
    "warnings": []
  }
}
```

### 4. 결과 JSON

기술성 결과는 기존 공통 필드에 `subscores`와 `technology_metrics`를 포함한다.

```json
{
  "axis": "technology",
  "label": "기술성",
  "score": 0,
  "subscores": {
    "technical_differentiation": {
      "score": 0,
      "max_score": 50
    },
    "implementation_specificity": {
      "score": 0,
      "max_score": 50
    }
  },
  "technology_metrics": {
    "representative_cpc": "...",
    "representative_ipc": "...",
    "country_code": "...",
    "similar_patents": []
  }
}
```

## 실행 방법

전체 workflow에서 기술성은 기존 `technology` 축으로 실행된다.

```bash
cd /Users/hangyu/workspace/PatentFlow_Agent
source .venv/bin/activate
python -m app.main P201702001-KR0
```

기술성만 빠르게 검증할 때는 아래 단독 스크립트를 사용한다.

```bash
cd /Users/hangyu/workspace/PatentFlow_Agent
source .venv/bin/activate
python scripts/evaluate_technology_only.py P201702001-KR0
```

실행 중에는 아래 단계 로그가 출력된다.

- 특허 DB 조회
- KIPRIS 서지/청구항 조회
- 대상 특허 PDF 수집 및 markdown 변환
- 대상 특허 전처리 및 CPC/IPC 추출
- 선행기술조사문헌 우선 수집
- 국내특허는 대표 CPC, 해외특허는 대표 IPC와 국가 기준으로 유사 특허 후보 검색
- embedding similarity 기반 비교군 보완
- 비교군 특허 PDF 수집 및 도면/이미지 제거 후 원문 텍스트 입력
- 기술성 LLM 평가
- JSON 및 Markdown 리포트 저장

결과는 기본적으로 아래 경로에 저장된다.

```text
artifacts/runs/manual/technology_only_<timestamp>_<management_number>/
├── technology_eval_result.json
└── technology_eval_report.md
```
