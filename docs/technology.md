# 기술성 평가 기준 및 구현 계획

기술성 평가는 대상 특허의 기존 기술 대비 차별성과 문헌 내 구현 구체성을 종합해 100점 만점으로 산정한다.

```text
기술성 점수(100)
= 기술 차별성(60)
+ 구현 구체성(40)
```

## 1. 기술 차별성 (60점)

### 목적

기존 기술과 비교했을 때 대상 특허가 기술적으로 무엇이 다른지 평가한다.

### 사용 데이터

- 대상 특허 PDF 원문
- 유사 특허 PDF 원문

### 평가 방식

```text
대상 특허 입력
→ KIPRIS API로 대상 특허 메타데이터 조회
→ 대상 특허 PDF 원문 수집
→ 대상 특허의 제목·초록·대표 청구항·기술 구성 추출
→ 대표 CPC 추출
→ 대표 CPC 기준 유사 특허 후보 검색
→ KR 등록/공개 특허 필터링
→ 대상 특허 출원일 이전 특허 필터링
→ 대상 특허 출원일 기준 최근 10년 특허 필터링
→ 개인 출원 제외 필터링
→ 후보 유사 특허 메타데이터 조회
→ 후보 유사 특허의 제목·초록 추출
→ 제목+초록 기반 embedding similarity 계산
→ 유사도 상위 Top 3 유사 특허 선정
→ Top 3 유사 특허 PDF 원문 수집
→ LLM이 대상 특허와 Top 3 유사 특허 비교
→ 공통 기술 요소 및 차별 기술 요소 추출
→ 기술 구조 차별 요소 분석
→ 기술 차별성 점수 산정
```

### 판단 요소

| 판단 요소 | 설명 |
| --- | --- |
| 기술 구조 차별성 | 기존 유사 특허 대비 새로운 구성요소 및 기술 조합 차이가 존재하는지 |

### 점수화 기준

| 평가 항목 | 판단 기준 | 점수 |
| --- | --- | ---: |
| 신규 구성요소 존재 | 유사 특허에 없는 새로운 구성요소가 확인됨 | 15 |
| 기술 조합 차별성 | 기존 구성요소를 결합하는 방식이 다름 | 15 |
| 처리 구조 차별성 | 데이터·신호·공정·제어 흐름이 유사 특허와 다름 | 15 |
| 해결 방식 차별성 | 같은 문제를 다른 방식으로 해결하거나 다른 기술적 효과를 냄 | 10 |
| 차별 근거 명확성 | 차별 요소가 청구항·상세설명 등 문서 근거로 확인됨 | 5 |
| 합계 |  | 60 |

## 2. 구현 구체성 (40점)

```text
구현 구체성 점수(40)
= 입력·처리 요소 구체성(15)
+ 구현 로직 구체성(25)
```

## 2-1. 입력·출력 구성요소 구체성 (15점)

### 목적

기술 구현에 필요한 입력 데이터, 처리 대상, 핵심 변수, 출력 결과가 구체적으로 설명되어 있는지를 평가한다.

### 사용 데이터

- 대상 특허 PDF 원문

### 판단 요소

| 판단 요소 | 설명 |
| --- | --- |
| 입력 데이터 명시 | 어떤 입력값·데이터·조건을 사용하는지 |
| 처리 대상 명시 | 어떤 객체·정보·상태를 처리하는지 |
| 핵심 변수 활용 | 특징값·조건값·제어값 등이 설명되는지 |
| 출력 결과 구조 | 어떤 결과를 생성하는지 설명되는지 |
| 구성요소 구체성 수준 | 단순 기능 수준이 아닌 실제 구성요소 수준까지 설명되는지 |

### 점수화 기준

| 평가 항목 | 판단 기준 | 점수 |
| --- | --- | ---: |
| 입력 데이터 명시 | 사용하는 입력값·데이터·조건이 명확히 제시됨 | 4 |
| 처리 대상 명시 | 어떤 객체·정보·상태를 처리하는지 제시됨 | 3 |
| 핵심 변수 명시 | 특징값·조건값·제어값 등 핵심 변수가 제시됨 | 3 |
| 출력 결과 구조 | 생성되는 결과·산출물·판단값이 제시됨 | 3 |
| 구성요소 연결성 | 입력→처리대상→출력 간 관계가 설명됨 | 2 |
| 합계 |  | 15 |

## 구현 반영 계획

### 1. 유사 특허 후보 수집

- 대표 CPC는 전처리된 PDF metadata의 `cpc` 첫 번째 값을 사용한다.
- KIPRIS `cpcSearchInfo`로 동일 CPC 후보를 조회한다.
- 후보 필터:
  - KR 등록/공개 특허
  - 대상 특허 출원일 이전
  - 대상 특허 출원일 기준 최근 10년
  - 대상 특허 자기 자신 제외
  - 개인 출원 제외

### 2. Top 3 유사 특허 선정

- 후보의 `title + abstract`와 대상 특허의 `title + abstract`를 embedding한다.
- cosine similarity 기준 상위 3건을 선택한다.
- 유사 특허 PDF는 가능한 경우 수집하고 markdown으로 파싱한다.
- PDF 수집 실패 시 제목/초록/청구항 metadata만으로 비교하되, missing 정보에 남긴다.

### 3. 기술성 LLM 입력

기술성 prompt에는 아래 값을 추가한다.

```json
{
  "technology_metrics": {
    "representative_cpc": "...",
    "similar_patents": [],
    "similar_patent_count": 3,
    "candidate_count": 0,
    "warnings": []
  }
}
```

### 4. 결과 JSON

기술성 결과는 기존 공통 필드에 `sub_scores`를 추가한다.

```json
{
  "axis": "technology",
  "label": "기술성",
  "score": 0,
  "sub_scores": {
    "technical_differentiation_score": 0,
    "implementation_specificity_score": 0,
    "input_output_specificity_score": 0,
    "implementation_logic_score": 0
  },
  "technology_metrics": {
    "representative_cpc": "...",
    "similar_patents": []
  }
}
```

## 실행 방법

전체 workflow에서 기술성은 기존 `technology` 축으로 실행된다.

```bash
cd /Users/hangyu/workspace/PatentFlow_Agent
source .venv/bin/activate
python -m app.main P201702001-KR0
```

기술성만 빠르게 검증할 때는 아래 단독 스크립트를 사용한다.

```bash
cd /Users/hangyu/workspace/PatentFlow_Agent
source .venv/bin/activate
python scripts/evaluate_technology_only.py P201702001-KR0
```

실행 중에는 아래 단계 로그가 출력된다.

- 특허 DB 조회
- KIPRIS 서지/청구항 조회
- 대상 특허 PDF 수집 및 markdown 변환
- 대상 특허 전처리 및 CPC 추출
- 대표 CPC 기준 유사 특허 후보 검색
- embedding similarity 기반 Top 3 선정
- Top 3 유사 특허 PDF 수집 및 도면/이미지 제거 후 원문 텍스트 입력
- 기술성 LLM 평가
- JSON 및 Markdown 리포트 저장

결과는 기본적으로 아래 경로에 저장된다.

```text
artifacts/runs/manual/technology_only_<timestamp>_<management_number>/
├── technology_eval_result.json
└── technology_eval_report.md
```
